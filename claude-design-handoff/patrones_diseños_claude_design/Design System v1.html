Migración 3 paletas → 1

aliases de compat en tokens.css

El proyecto tiene tres surfaces con la misma identidad pero tokens distintos. La nueva paleta --arc-* / --forge-* / --state-* es canónica. Los nombres viejos siguen funcionando vía aliases — borrá el bloque de compat al final de tokens.css cuando termines de migrar cada surface.

Plan de migración por surface

  1. Draft Advisor SPA (draft_advisor/static/styles.css) — ya está cerca. Cambiar el bloque :root { --gold: …; --blue: …; } por un @import "tokens.css". Las clases existentes siguen funcionando vía aliases.
  2. Match History + Splash Viewer (templates Jinja2) — extraer el <style> inline a un .css compartido en templates/_shared/. Importar tokens canónicos. Reemplazar --hextech-* → --arc-* con find-replace.
  3. Dashboard enhanced (dashboard_enhanced.py) — el HTML embebido como string usa --primary/--secondary/--accent. Arrancar por extraer el HTML/CSS a un template Jinja2 separado, después aplicar el find-replace.
  4. Listo para borrar el bloque de compat al final de tokens.css cuando ningún grep de los nombres viejos devuelva resultados.
07

Hallazgos · decisiones · próximos pasos

Decidido

WCAG: AA texto normal, AAA crítico

Para texto chico sobre navy, agregué --arc-gold-text (#d4b15c, 7.4:1) en lugar de aclarar el dorado primario. El gold #c89b3c queda para áreas grandes (CTAs filled, headings — 5.8:1 AA).

Decidido

--purple eliminado del sistema

Estaba declarado pero sin uso semántico claro. Si más adelante necesitás un quinto color (mood/featured), lo agregamos con un rol específico — no como decoración suelta.

Decidido

--remake → --state-neutral

Generalizado. Todo lo "indefinido / incompleto / N/A" usa el mismo gris-azulado: partidas remake, slots vacíos, datos pendientes.

Atención

Mobile real, no solo "se rompe menos"

Touch targets ≥44px en todo botón / slot. El SPA actual tiene slots de 80px que en mobile quedan apretados — el sistema los marca como mínimo 80px pero el grid 5-col puede colapsar a 3 + scroll horizontal en <640px.

Atención

Estado disabled agregado a .recommend-btn

Necesitás disparar disabled cuando faltan slots aliados. El componente lo soporta vía disabled attr o aria-disabled="true". Acordate de bloquear el handler también en JS.

A futuro

i18n — solo ES-AR por ahora

Tokens semánticos, copy hardcodeado. Si se planea EN/PT-BR, separar strings a un dict de Python primero, después un sistema mínimo de {{ t.recommend_pick }} en Jinja2.

A futuro

Self-host de fuentes

Por ahora Google Fonts CDN con preconnect (rapidez). Para offline-first en exports HTML autocontenidos, self-hostear Inter + Outfit (woff2) y embeber base64 — deuda conocida.

A futuro

Default target_role parametrizado

No lo hardcodeo en CSS. El JS del SPA debería leerlo de localStorage o de un endpoint /api/v1/draft/preferences — así dejás que el usuario elija una vez y el sistema lo recuerda.
