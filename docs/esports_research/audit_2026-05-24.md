al plan original** (`cuddly-sprouting-newell.md` previo). Cumple los
6 puntos de compliance Riot, los 4 adapters reales tienen interfaz

## 1. Arquitectura y diseño

### Lo que está bien

- **Separación módulo/router clara**: `esports_research/` (dominio) ↔
  `meta_api/routes/esports.py` (HTTP) ↔ `meta_scraper/adapters/esports/`
  (extracción). Sigue el mismo patrón que `jungle_research/`.
- **Storage bronze/silver/gold canónico**: `data/esports_research/` con
  `bronze/<source>/`, `silver/<entity>/`, `gold/<feature>.json`.
  Persistencia atómica vía `_write_json_atomic`.
- **Schemas Pydantic V2 completos** (`schemas.py` 172 líneas, 100%
  cubierto): `Tournament`, `Match`, `Game`, `DraftAction`, `Team`,
  `Player`, `ParticipantGame`, `Patch`, `ChampionDim`,
  `CounterpickEntry`, `ComfortScore`. Todos con `extra="allow"`.
- **`BaseEsportsAdapter` correctamente encima de `BaseAdapter`**: hereda
  retry/rate limit + agrega `robots_allowed()`, User-Agent identificable
  con email, manejo de 403 como `PermissionError`.
- **Source registry de 12 fuentes** persistido en JSON con `Source`
  schema validado (igual que jungle_research).

### Issues encontrados

| # | Severidad | Issue | Costo fix |
|---|-----------|-------|-----------|
| A.1 | Media | `base_esports.py` coverage 38% — los paths de retry/429/robots no se exercise en tests | ~1h |
| A.2 | Baja | `BaseEsportsAdapter._safe_get` reimplementa `_safe_get` de `BaseAdapter` (no llama `super()`). Comportamiento diverge: distinto retry, distinto manejo de 403. Difícil mantener en paralelo | ~30min |
| A.3 | Baja | `routes/esports.py` (244 líneas) tiene lógica de lectura de gold features inline (`_read_counterpicks`, etc.). Podría delegarse a `esports_research/queries.py` para mantener el router como adaptador HTTP delgado | ~1.5h |

## 2. Calidad de código

### Lo que está bien

- **`leaguepedia.py`** usa Cargo API correcta, paginación con `limit=500`
  y `offset` (respeta documentación oficial), auth opcional via env
  (`LEAGUEPEDIA_USER` + `LEAGUEPEDIA_BOT_PASSWORD`) con gap visible si
  ausente.
- **`oracles_elixir.py`** descarga CSV vía URL S3 oficial. Parsing con
  `csv.DictReader`. Métodos `fetch_matches`/`fetch_game_detail`/
  `fetch_draft` devuelven gap claro ("requires CSV snapshot context",
  "CSV does not include full pick/ban order").
- **`gol_gg.py`** llama `robots_allowed(url)` antes del fetch real
  (compliance correcta). `min_delay=4.0`/`max_delay=8.0` respeta rate
  limit conservador. Parser BeautifulSoup.
- **`data_dragon.py`** usa endpoint público sin auth, resolución de
  `latest` con `/api/versions.json`, parsing de campeones con
  `primary_role` desde tags. Métodos no aplicables (tournaments/matches/
  game/draft) devuelven gap claro.
- **6 stubs cumplen contrato**: heredan de `BaseEsportsAdapter`, retornan
  `status: not_implemented` con razón.
- **VOD adapter** explícito en docstring: *"never downloads or rehosts
  video bytes"* + modela solo `VodMetadata` Pydantic.

### Issues encontrados

| # | Severidad | Issue | Costo fix |
|---|-----------|-------|-----------|
| B.1 | Media | `gol_gg.parse_draft_html` usa selectores genéricos (`.draft .champion`, `.picks-bans img`) y marca todas las actions como `action_type=PICK` con `team_side=UNKNOWN`. Estructura placeholder — cuando se active necesita selectores reales validados contra HTML actual | ~2-3h por adapter activado |
| B.2 | Media | `leaguepedia.cargo_query` no maneja explícitamente el caso `payload.get("error")` que devuelve la API en queries malformadas. Pasa silencioso a `cargoquery=[]` | ~30min |
| B.3 | Baja | `oracles_elixir.parse_csv_text` llama `list(csv.DictReader(StringIO(text)))` — carga todo en memoria. Para CSVs anuales (~30MB+) podría doler. Por ahora OK con datasets demo | ~1h (streaming) |
| B.4 | Baja | `data_dragon.fetch_champions("latest")` hace 2 requests (versions.json + champion.json). No cachea `latest_version` entre invocaciones | ~30min |
| B.5 | Baja | `routes/esports.py` repite estructura `_ok(source=..., data=..., gaps=[...])` decenas de veces. Helper sirve pero podría ser un decorator/respuesta tipada | ~1h refactor |

   Bloquea monitoring + UX de "qué está saludable".
5. **C.5 — Test del endpoint `/ingest` dry-run** (~30min). Quick win
   que cierra un hueco evidente de la suite.
